OpenAI DevDay 2026総まとめ

20を超える発表を貫くテーマは、モデル単体の賢さではない。エージェントを動かし、監督し、外部サービスにつなぎ、チームで成果を確認するための「実行基盤」が一気に製品化されたことだ。

先に結論。 DevDay 2026でOpenAIは、ChatGPT、Codex、APIを別々の製品として進化させるのではなく、同じエージェント基盤の異なる入口として接続した。

特に注目したいのは、Codex Cloudと新しいCLI、Agents API、MCP Events、Code Review、ChatGPT Spaceである。これまで個別ツールで組み立ててきた「複数エージェントの実行・監督・レビュー・継続作業」が、OpenAIの標準機能へ寄ってきた。

発表全体を一枚で見る

公式recapでは、DevDay 2026を5つの領域に分けている。開発者目線では、次の4層として捉えると関係が分かりやすい。

共同作業面 Dots / Space / Pages / Slides / Team Tasks / Slack・Teams / Meetings
接続・配布面 Plugin Extensions / MCP Events / Sites / Profiles / Sign in with ChatGPT / Marketplace
エージェント実行基盤 Codex Cloud / Codex CLI / Code Review / Security Cloud / Agents API / Decisions API / Bedrock
モデル・計算資源 GPT-6.1 Sol / Ultrafast / Private Intelligence / Pro 500

上の層ほど人やチームに近く、下の層ほど推論と実行の基盤に近い。今回の重要点は、4層が一度に揃ったことにある。

全発表を4つのテーマで整理する

1. モデルは「最高性能」だけでなく、速度と費用で使い分ける

GPT-6.1 Solは、コーディング、Computer Use、業務タスクを主眼にした標準モデルで、公式にはAstraに近い能力をより低い価格で提供すると説明されている。API価格は入力100万トークンあたり2ドル、出力100万トークンあたり10ドルで、105万トークンのコンテキストを持つ。

Ultrafastは別モデルではなく高速実行のプレミアム層で、AstraではCodex上で最大8倍、APIで最大6倍の生成速度を掲げる。あわせて、Zero Data Retention、Private Safety Processing、今秋予定のPrivate Inferenceを束ねたPrivate Intelligenceも発表された。

これは「一番賢いモデルを常に使う」設計から、通常処理はSol、難所はAstra、待ち時間が価値を左右する箇所はUltrafastという、ワークロード別のモデル運用への移行である。

2. CodexとAgents APIが、エージェントの実行基盤になる

Codex Cloud

再利用可能な開発環境を公開し、PCがスリープ中でもタスクを継続する。Web、モバイル、デスクトップからレビューと追加指示ができる。

刷新されたCodex CLI

音声でタスクを開始・修正し、/agentsで複数タスクを監督する。worktree、セッション再開、プロンプト編集も改善された。

Code Review

デスクトップアプリでPRやMRの概要、diff、コメント、チェックを読み、Codexへ調査を依頼できる。自動クラウドレビューにも対応する。

Codex Security Cloud

リポジトリ全体や新規コミットを継続スキャンし、重複整理、根拠提示、修正案の作成までをクラウドで行う。

Agents API + Computer Use

CodexのハーネスをマネージドAPIとして提供する。セッション、回復、コンテキスト圧縮、マルチエージェント、MCP、ブラウザ操作を組み込める。

Decisions API / Bedrock

有限の選択肢に絞った低遅延の判断APIと、OpenAIのエージェントをAWS管理下の資源で動かすBedrock Managed Agentsが加わった。

特に注目

OrcaのようなAgent Development Environmentで見えていた方向が、Codex本体にも入った。 ターミナルで一体のエージェントと対話するだけでなく、タスクごとの環境を分け、複数の仕事を並行させ、人間が差分と結果を監督する。競争軸はコード補完の精度から、エージェント群の待ち時間・状態・成果物をどう管理するかへ移っている。

3. MCPとプラグインが「呼び出す道具」から「常駐するアプリ」へ進む

Plugin Extensionsにより、プラグインは会話中にToolとして呼ばれるだけでなく、サイドバーのフルスクリーンアプリ、会話横のパネル、独自ファイルビューア／エディタ、Composerから参照できるコンテンツとしてChatGPTへ組み込める。Sitesでプラグインをホストする仕組みや、作成・審査・発見性の改善も加わった。

さらに重要なのがMCP Eventsである。ユーザーは「新しいレビューコメントが付いたら修正案を作る」のような監視条件を指定し、MCP ServerはWebhookでChatGPTへイベントを届ける。これはMCP 2026-07-28を前提とし、events/list、events/subscribe、events/unsubscribeを使う。

人が毎回プロンプトを送るPull型から、業務イベントがエージェントを起動するPush型へ。

特に注目

MCPのステートレス化が、実運用のイベント駆動までつながった。 以前整理したMCP 2026-07-28では、初期化セッションをなくし、通常のHTTP基盤へ寄せた点が大きな変更だった。MCP Eventsはその上に永続subscriptionとWebhookを足す。つまり「RPC自体はステートレス、監視したい業務状態は明示的なsubscriptionとして管理する」という責務分離になっている。

4. ChatGPTが、会話画面からチームの作業空間へ広がる

Dotsは、継続的な責務を引き受ける常駐型エージェントである。接続したアプリとクラウドコンピューターを使い、スケジュールや委任タスクをバックグラウンドで進める。アクションごとに「自動実行」「明示指示があるときだけ」「事前確認」「人へ引き渡す」といったルールを設定できる。

ChatGPT SpaceとPagesは、会話を越えて人とエージェントが共有知識と成果物を育てる場所になる。共同編集スライド、Team Tasks、SlackとMicrosoft Teamsでの@ChatGPT、会議記録をSpaceへ保存するMeetings pluginも同じ方向にある。

そのほか、Sitesやプラグインを公開するShareable Profiles、外部サービスでChatGPTアカウントと利用枠を使うSign in with ChatGPT、月額500ドルのPro 500、企業のOpenAI契約枠を提携ソフトウェアへ使うOpenAI Marketplaceも発表された。

特に注目

長期記憶の論点が、保存方式から共同作業の単位へ広がった。 個人・チーム・会社の記憶をどう分けるかという問題に対し、Spaceは共有境界、Pagesは人とAIが更新する成果物、Dotsは継続的に保守する主体として機能する。検索精度だけでなく、誰が所有し、誰が更新し、どのエージェントが行動できるかが設計の中心になる。

利用可能時期と注意点

発表時点で使えるものと、限定公開・近日提供のものが混ざっている。2026年9月30日時点の公式情報では、主な状況は次の通り。

  • GPT-6.1 Sol： API、Plus、Pro、Business、Enterprise、Eduで利用可能。
  • Astra Ultrafast： APIおよびPro 500 / EnterpriseのCodex・ChatGPT Workで利用可能。Sol版は近日提供。
  • Codex Cloud / CLI / Code Review： Codex Cloudは複数プラン、CLIとCode Reviewは全プラン向け。組織設定や接続権限は別途必要。
  • Agents API + Computer Use： APIおよびPro 500 / EnterpriseのCodex・ChatGPT Workで提供。
  • Decisions API： 限定プレビュー。広範な提供は数日以内と案内されている。
  • Collaborative Slides： 今後数週間で提供予定。
  • Private Inference： 今秋プレビュー予定。

提供プラン、地域、価格、プレビュー条件は変わりやすい。導入前に各公式ドキュメントを再確認したい。

実務でどう評価するか

新機能を一度に導入する必要はない。まずは一つの開発フローを、次の順番で小さく検証すると違いが見えやすい。

  1. 実行を分離する： Codex Cloudの環境とworktreeを使い、並行タスクが互いに干渉しないか確認する。
  2. 判定器を置く： Unit / Integration TestとCode Reviewを組み合わせ、エージェントが短い周期で修正できる状態にする。
  3. イベントで起動する： MCP Eventsでレビューコメントなど一種類だけを購読し、誤作動時の停止手段を用意する。
  4. 権限を絞る： 読み取り、自動実行、事前承認、人への引き渡しを操作単位で決める。
  5. 人の待ち時間を測る： モデルのベンチマークだけでなく、依頼からレビュー可能な差分が出るまでの時間と、手戻り回数を比較する。

まとめ

DevDay 2026で最も大きく変わったのは、モデルの数字ではなく、AIを仕事の流れへ組み込むときの部品が揃ったことだ。Codexはコードを書く道具から複数タスクを監督する環境へ、MCPはツール呼び出しからイベント購読へ、ChatGPTは会話画面から共有作業空間へ広がった。

一方で、実行範囲が広がるほど、テスト、レビュー、権限、状態の所有者が重要になる。次に試すべきは「どのモデルが一番賢いか」ではなく、どの仕事をエージェントへ渡し、どの判定を自動化し、どこで人が止めるかを小さな実例で設計することだ。
